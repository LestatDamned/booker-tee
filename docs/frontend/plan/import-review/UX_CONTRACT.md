# Import Review UX Contract

Статус: accepted direction, implementation in progress.

## Тип страницы

Import Review — это `bank-feed reconciliation workbench`: рабочая очередь,
в которой пользователь сверяет результат парсинга выписки, придаёт строкам
финансовый смысл и только после явного решения проводит их в ledger.

Экран не является обычной CRUD-таблицей, отчётом или техническим интерфейсом
парсера. Его основной цикл:

```text
увидеть состояние → понять предложение → подтвердить
                                      ↘ исправить исключение → подтвердить
```

## Иерархия страницы

1. Компактная сверка выписки: поступления, списания и состояние расхождения.
2. Прогресс и фильтры очереди.
3. Плотные строки с хорошо различимыми датой, описанием, суммой и состоянием.
4. Одно primary action, зависящее от состояния строки.
5. Раскрытая панель только для решения или исправления исключения.

Доход, расход и перевод различаются цветом и обязательной текстовой меткой.
Цвет не является единственным носителем смысла.

## Состояния и действия строки

| Состояние | Primary action | Secondary action |
| --- | --- | --- |
| Автоправило заполнило подтверждаемый смысл | Подтвердить | Изменить |
| Есть обычное предложение | Проверить предложение | — |
| Нет категории | Выбрать категорию | — |
| Есть кандидат в перевод/сопоставление | Проверить перевод | — |
| Категория выбрана, строка не проведена | Проверить и провести | — |
| Строка проведена | спокойный статус | отмена в дополнительных действиях |

Предложение никогда не означает silent posting. Финансовая операция создаётся
только после явного действия пользователя.

## Категоризация

- Для обычной строки знак суммы определяет доход или расход.
- Универсальный select `Доход / Расход / Перевод / Корректировка` не является
  частью основного сценария.
- Категория — первое обязательное поле, объект — второе необязательное.
- Изменение category/property автоматически запускает server evaluation.
- Отдельная кнопка `Проверить выбор` не нужна.
- Перевод открывает отдельный flow и не конкурирует с полями категории.
- Создание категории раскрывается по запросу и возвращает пользователя в
  текущий draft.

## Автоправила

Создание правила всегда является отдельным осознанным выбором пользователя.

- Пользователь включает `Создать правило для похожих строк`.
- Пользователь обязан самостоятельно ввести устойчивый текст совпадения,
  например `КРАСНОЕ&БЕЛОЕ`.
- Полное банковское описание не становится pattern автоматически.
- Интерфейс может показать исходное описание как справку, но не заполняет и не
  сохраняет условие без подтверждения пользователя.
- Пустой pattern блокируется и клиентом, и command boundary до posting.
- Созданное из review правило предлагает смысл похожим строкам; оно не проводит
  их молча.

Будущее улучшение: до сохранения показывать количество строк текущей выписки,
которые соответствуют введённому pattern, и предупреждать о слишком широких
условиях.

## Техническая трассировка

Raw и normalized данные сохраняются, но не стоят перед финансовым решением.
Они доступны через вторичное раскрытие `Сверить с исходной строкой`. При
существенной ошибке нормализации интерфейс может поднять конкретное проблемное
поле в основной поток.

## Доступность и адаптивность

- Все действия доступны с клавиатуры и имеют видимый focus.
- Минимальная touch-зона интерактивных элементов — 44 px.
- Ошибки связаны с соответствующими полями и объявляются assistive technology.
- На узком экране сохраняется порядок: дата/описание → сумма → смысл → действие.
- Технические и редкие действия раскрываются прогрессивно.
