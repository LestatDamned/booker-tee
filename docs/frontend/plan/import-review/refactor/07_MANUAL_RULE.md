# Этап 7. Ручное создание правила

Статус: completed.

## Цель

Дать пользователю полный контроль над устойчивым фрагментом шумного банковского
описания и заранее показать результат создаваемого правила.

## Scope

- Действие называется `Применять это решение к похожим строкам`.
- После включения показываются полное исходное описание и поле
  `Фрагмент описания`.
- Pattern не подставляется автоматически.
- Пользователь копирует и вставляет устойчивый фрагмент самостоятельно.
- Preview: `Если описание содержит «…» → категория «…»`.
- Пустой pattern блокируется до posting клиентом и command boundary.

## Критерии готовности

- [x] Полное описание доступно рядом как справка.
- [x] Поле имеет видимый label, helper text и локальную ошибку.
- [x] Ничего не сохраняется без явного согласия пользователя.
- [x] Rule creation и posting сохраняют текущую atomicity.
- [x] Созданное правило не подтверждает похожие строки автоматически.

## Реализовано

- Opt-in переименован в `Применять это решение к похожим строкам` и остаётся
  выключенным по умолчанию.
- После включения показывается полное raw-описание из выписки. Оно доступно для
  обычного выделения и копирования, но никогда не переносится в pattern
  автоматически.
- Поле переименовано в `Фрагмент описания`, ограничено теми же 255 символами,
  что и API boundary, и сопровождается примером устойчивого фрагмента.
- Пустой fragment получает локальную ошибку, `aria-invalid`, связь через
  `aria-describedby` и focus; запрос при этом не отправляется.
- Preview обновляется по мере ручного ввода:
  `Если описание содержит «…» → категория «…»`.
- Рядом явно сказано, что похожие строки только получат предложение и не будут
  проведены автоматически.
- Явная отмена редактора сбрасывает opt-in и введённый pattern; простое закрытие
  панели по-прежнему сохраняет локальный draft.
- Backend flow не изменялся: posting, создание правила и применение его к
  документу остаются в одной транзакции с rollback при ошибке.

## Корректировка после визуального review

- Убраны конкурирующие синие и зелёные боковые акценты у описания, итога
  операции и preview правила.
- Описание и настройка правила объединены в один спокойный контейнер: рядом на
  desktop и последовательно на узком экране.
- Повторяющиеся инструкции сокращены до одной подсказки у поля и одной короткой
  оговорки о том, что правило не проводит строки автоматически.
- Поле фрагмента приведено к общему виду остальных form controls.
