# Этап 2. Закрытая строка и система бейджей

Статус: completed.

## Цель

В закрытой строке быстро различать событие, финансовый смысл, состояние и
происхождение решения без визуального шума.

## Уже реализовано

- типы `Доход`, `Расход`, `Перевод` используют semantic tones;
- категория имеет единый мягкий category tone;
- статус отображается отдельной спокойной меткой;
- источник решения отделён от результата;
- автоправило объясняется двумя уровнями:
  `Предложено правилом` и `pattern → результат`;
- текущая workbench-компоновка сохранена; табличный header удалён.

## Завершено

- copy всех persisted statuses переведён на язык пользовательских состояний;
- технические состояния `Извлечено` и `Нормализовано` представлены как
  `Требует решения`, а неизвестный источник решения скрыт;
- подтверждённый финансовый смысл не подменяется устаревшим предложением
  правила;
- тестами покрыты строки без категории, все persisted statuses, активное
  автоправило и отсутствие повторов в его объяснении;
- дата, описание и сумма сохраняют текущую workbench-иерархию без перехода к
  табличной компоновке;
- UI audit пройден на desktop, tablet и mobile без горизонтального overflow.

## Не входит

- итог и действия справа — этап 3;
- выбор типа и transfer flow — этап 4;
- направление счетов — этап 8;
- общая редактура страницы — этап 9.

## Критерии готовности

- [x] Пользователь различает type, category, status и source без опоры только на
      цвет.
- [x] `Проведено` выглядит спокойнее problem/decision состояний.
- [x] Предложение не подменяет persisted operation facts.
- [x] В строке нет технического или повторяющегося copy.
- [x] Проверены desktop, tablet и mobile.
