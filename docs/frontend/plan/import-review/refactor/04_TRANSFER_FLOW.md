# Этап 4. Перевод как основной сценарий

Статус: completed.

## Цель

Сделать перевод равноправной финансовой интерпретацией строки, доступной без
меню редких действий.

## Scope

- В форме напрямую доступны обычная категоризация и перевод.
- Знак суммы продолжает определять income/expense для обычной операции.
- При выборе transfer категория и объект заменяются выбором второго счёта.
- Исходный счёт берётся из привязки документа.
- Возврат к обычной операции восстанавливает category/property draft.
- `На проверку`, `Игнорировать` и технические данные не смешиваются с выбором
  финансового типа.

## Критерии готовности

- [x] Transfer доступен без `Ещё действия`.
- [x] Нельзя выбрать тот же счёт как обе стороны перевода.
- [x] Draft не теряется при переключении сценария и закрытии панели.
- [x] UI использует server evaluation и не копирует transfer policies.
- [x] Focus и keyboard flow проверены.

## Реализовано

- В раскрытой строке добавлен постоянный переключатель `Расход/Доход` —
  `Перевод`; он использует native radio semantics и работает с клавиатуры.
- Обычный тип операции приходит в API как `ordinaryOperationType` и
  определяется серверной classification policy, а не знаком суммы в React.
- При выборе перевода category/property заменяются выбором второго счёта или
  готовой пары; направление сразу показывает пользовательские названия счетов.
- Исходный счёт и допустимые вторые счета остаются server-owned: исходный счёт
  исключён из списка до передачи DTO в UI.
- Category/property draft и выбранный вариант перевода сохраняются при смене
  режима и закрытии раскрытой строки.
- Строка с server-classified transfer сразу открывается в режиме перевода.
- Основное действие такой строки называется `Проверить перевод`.
