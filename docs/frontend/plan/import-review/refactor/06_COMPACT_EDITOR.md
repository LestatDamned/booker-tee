# Этап 6. Компактная форма изменения операции

Статус: completed.

## Цель

Сделать раскрытую форму компактным продолжением выбранной строки, а не
отдельной административной страницей внутри неё.

## Scope

- Уменьшить количество вложенных карточек, рамок и постоянных сообщений.
- Для обычной операции показывать category, optional property, outcome и
  confirm/cancel.
- Для transfer показывать source account, destination account, route, outcome и
  confirm/cancel.
- `Создать категорию` расположить рядом с category select как вспомогательное
  действие.
- Убрать постоянное success-сообщение о пройденных проверках; валидность
  выражается активной кнопкой.
- Ошибки и warnings остаются явными и локальными.

## Критерии готовности

- [x] Панель заметно компактнее текущей и не дублирует закрытую строку.
- [x] Основной сценарий читается сверху вниз без вложенных контейнеров.
- [x] Cancel восстанавливает последний server state.
- [x] Ошибка фокусирует первое проблемное поле.
- [x] Mobile не имеет горизонтального overflow.

## Реализовано

- У редактора убрана дополнительная карточка с фоном, рамкой и внутренним
  padding: панель продолжает раскрытую строку одним линейным потоком.
- `Создать категорию` перенесено в заголовок поля категории и оформлено как
  вспомогательное действие с сохранением доступной зоны нажатия.
- Для дохода и расхода добавлен компактный живой итог выбранного типа,
  категории и объекта; во время server evaluation вместо устаревшего итога
  показывается короткий pending-state.
- Для перевода направление стало компактным outcome-акцентом; основные поля,
  проведение и отмена идут последовательно без вложенной карточки.
- Постоянное success-сообщение `Проверки выбора пройдены` удалено: готовность
  выражает активная primary-кнопка. Blocking reasons и ошибки сохранены.
- Явная `Отмена` сбрасывает category/property, режим, transfer selection и
  локальные ошибки к последнему состоянию из DTO, закрывает панель и возвращает
  focus на действие строки. Закрытие крестиком по-прежнему сохраняет draft.
- Просроченные ответы evaluation и создания категории после cancel больше не
  могут вернуть отменённое локальное состояние.

## Корректировка после визуального review

- Рабочая ширина формы ограничена: на широком экране поля больше не
  растягиваются на всю строку операции.
- Семантический цвет переключателя дохода, расхода и перевода приглушён; цвет
  остаётся подсказкой, а не фоном крупной области.
- Итог операции собран в одну строку без отдельной цветной полосы.
- `Создать категорию` расположен рядом с подписью поля, а подтверждение и
  отмена собраны в одну группу действий.
